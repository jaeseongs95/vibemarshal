기술 검토

ledger.py:803에서 initialize는 journal 설정을 보류한 연결을 열고 :807에서
BEGIN IMMEDIATE를 실행한다. writer lock 뒤 :808의 identity/schema 조회는 같은
연결·transaction에서 수행된다. 경로 존재·파일 크기에 근거한 이전 판단을 없애
lock 직전 foreign writer가 commit한 DB를 새 DB로 잘못 취급하는 창을 닫았다.
일반 connection의 PRAGMA foreign_keys, busy_timeout, synchronous는 connection
설정이며 이 경로는 identity 검사 전에 journal_mode=WAL을 실행하지 않는다.

DDL은 :815의 line accumulation과 sqlite3.complete_statement로 분리하여
connection.execute로 실행한다. 현재 static SQL의 trigger 내부 semicolon을
분할하지 않으며 execute 실패와 미완성 tail은 transaction 안에서 거절된다.
schema_meta insert, application_id=0x464D4531, user_version=4도 같은 transaction
안에 있고 :834의 단일 commit이 경계다. 영구 회귀는 trace의 BEGIN IMMEDIATE,
COMMIT 경계와 commit 직전 별도 reader가 빈 schema/zero identity만 보는 것을
검사했다. DDL, metadata, 두 identity pragma, precommit exception, KeyboardInterrupt,
secondary rollback failure 각각에 대해 rollback/close/retry가 통과했다.

crash 영구 회귀는 Linux spawn child에서 첫 CREATE TABLE 직후 os._exit(71),
application_id 직후 os._exit(72)를 실제 실행했다. parent가 종료 code와 rollback된
schema/identity를 확인하고 initialize retry 후 identity/integrity/FK를 검사했다.
이는 process 종료/reopen의 근거이며 power-loss나 storage flush 실패 근거는 아니다.

foreign 보존 영구 회귀는 missing/preexisting path에서 lock 직전 별도 spawn writer의
commit을 거절했고 main bytes·foreign data·identity·DELETE journal을 보존했다.
view-only, nonzero application_id-only 및 nonzero user_version-only DB도 거절·보존됐다.
독립 live-WAL 사례에서는 foreign committed data가 WAL에 있는 상태로 keeper 연결을
유지했다. initialize는 거절했고 main/WAL bytes, dump, identity, WAL journal mode가
그대로였다. -shm은 SQLite의 일시적 coordination state여서 byte identity를 주장하지
않는다. foreign hot-journal recovery나 모든 OS/filesystem 동작으로 일반화하지 않는다.

_assert_identity(:847)의 borrowed connection 성공·거절은 caller transaction/connection을
닫거나 commit/rollback하지 않았다. 자체 연 연결만 :887에서 닫는다. 내부 borrowed
연결은 _connect가 sqlite3.Row로 설정한 handle이다. 기존 identity 검사 범위(메타와
필수 6개 table 및 두 pragma)는 유지됐고 기존 DB의 모든 schema 객체·trigger를
재검증하는 완전한 integrity attestation으로 강화한 변경은 아니다.

_connect의 BaseException 경로는 acquired connection을 명시 close하고 close 오류가
최초 setup 예외를 대체하지 않도록 한다. malformed 파일 회귀가 bytes 보존, acquired
handle 명시 close, artifact root 미생성을 검사했다. setup 오류는 read/write 모두
secondary close 오류와 함께 검사됐다. initialize의 rollback secondary error도 최초
예외를 보존한다. 다만 :844 finally close는 T01의 기존 이중 실패 한계를 남긴다.

schema/identity를 되돌리지 않는다. 영구 synthetic WAL exception 검사와 독립 실제

artifact root가 없었다. reader를 해제한 뒤 retry는 dump를 그대로 유지하며 WAL과
