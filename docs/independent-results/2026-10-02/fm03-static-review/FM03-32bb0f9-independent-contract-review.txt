기존 첨부 source packet을 읽은 독립 정적 검토다. 17개 Python 파일을 AST parse하고

3. host-neutral 공통 계약에 필요한 최소 불변조건 (제안, 채택 아님)

공통 policy는 vendor별 executable, SDK, 토큰, 세션 파일, AGS 내부 저장 구조를 import하지
않고 typed input/output으로 표현한다. 최소 binding은 authorization reference/revision,
project/Task/Attempt, exact source closure digest, requested role/model/effort, profile,
canonical request digest, immutable absolute deadline, effect identity 및 관측 provenance다.
producer/host가 발행한 값과 adapter/provider가 관측한 값을 별도 필드로 유지한다.
승인 source 소유자는 VM Core, gate verdict 소유자는 AGS, 프로세스/Job 관측 소유자는
host adapter, 제품 completion 소유자는 Core다. 공통 policy가 이 권위를 합치지 않는다.
profile은 explicit selection이며 same-user assertion을 protected-VM truth로 승격하지 않는다.

시간 계약의 검토 oracle: 원 승인 Task 기한 T+5400은 tick/resume/restart로 연장하지 않는다.
full stage 900, 기타 stage 300은 상한으로 적용하고 효과 시작까지의 대기, interrupt,
cleanup, 최종 raw save가 어느 예산에 속하는지 현행 profile에서 고정한다. 실제 START
직전 fresh UTC와 local-derived monotonic 양쪽의 더 이른 기한을 사용하고, 부족한
전체 reserve에서는 시작을 거절한다. monotonic 숫자는 다른 process/boot로 무증명 이전하지 않는다.
기존 S0의 15+15를 현행 fullcaller의 승인값이라고 가정하지 않는다.

4. 최소 discriminating test plan (모두 미실행)

  소비된 ticket 재사용도 0. projection 성공만으로 시작하지 않는지를 구분한다.

T3 fullcaller900 / other300 / Task5400:
  full, other stage를 각각 테스트하되 전체 900/300을 기다릴 필요 없이 승인된 clock seam의

T4 running UTC+3 / clock / interrupt:
  기존 r7 결과는 재사용 가능한 endpoint 관측으로만 묶고 재실행하지 않는다. 새 fullcaller

5. 가장 작은 남은 vertical path와 필요한 전달물

먼저 current Windows kit를 정확한 32bb source closure와 결속해 정적 대조한다. 필요한
파일 이름은 발견한 과거 caller의 실제 reference 기준이며, 현행 이름이 다르면 publisher가
old→current mapping과 hash를 제공해야 한다. 아래 내용 자체가 실행 승인이나 credential은 아니다.

  - 현행 fm03_guard.py, bounded-foreground.py, 실제 fullcaller entrypoint;
    fixed_caller.py, s0_host_window.py 및 host-bridge/parent-port의 현재 구현.
  - discover-main.py, verify-installed.py, verify-entrypoint-paired.py, observe-inputs.py,
    supervisor-fixture.py, supervisor-smoke.py, prepare-seal.py, pure-selfcheck.py,
    cleanup-selfcheck.py (과거 scripts-final.json에서 요구한 전체 11개 집합과 비교).
  - manifests/scripts-final.json, fixed-inputs.json, preparation-r4-seal.json 및
    tracked-source.json; 현행 closure의 빠진 transitive 파일과 source→32bb mapping.
  - FIXED-INPUTS.json의 V02-d/V03-b 또는 현행 fullcaller profile, payload entrypoints,
    fixed130의 ordered ID manifest/loader/fixture hashes. 토큰·전체 환경 dump는 제외.
  - 현행 adapter/Job launcher, authority-read bridge, beginEffect가 실제 있는 module과
    public interface/schema 및 callsite. beginEffect 이름만 있는 계약은 구현 증거가 아니다.
  - execution-go의 비밀 없는 binding projection/schema: 승인 reference·digest/revision,
    consumed 상태, source closure, task/stage budget 및 기산점. native message 원문·실제
    credential·운영 DB/WAL은 전달하지 않는다. 실제 읽기 권위는 원 host에 유지한다.
  - r7 원 evidence와 independent POST의 publisher 제공 immutable GitHub ref, 상대 파일명,
    SHA-256 및 결과 schema. 지금 handoff에는 정확한 ref/파일명이 없으므로 발명하지 않는다.

그 다음 T1/T2/T3/T5/T6/T7의 순수 정책 판별을 현행 kit의 공개 경계에 연결하고 결과를
별도로 남긴다. 연결 source가 없으면 NOT_RUN이며 Linux fake로 채우지 않는다.
마지막으로 native 소유자가 새로 승인된 별도 fullcaller 슬롯 한 개에서 source→approval
projection→reserve→bind→admit→beginEffect→기존 adapter→unknown/validation을 끝까지
연결한다. r7 consumed endpoint는 재사용 실행하지 않고 digest로만 인용한다. 최소 우선
case는 T3의 setup 지연과 T5의 save 경합 중 정적 검토로 아직 갈라지지 않은 한 case다.
정상 완료는 별도 요구이며 fault-path unknown 관측을 fullcaller 성공으로 집계하지 않는다.
나머지 요구는 관측이 있을 때만 채운다. 이 검토에서 모든 항목의 채택·실행 승인은 하지 않는다.
